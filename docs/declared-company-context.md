# Declared company context

`POST /company-service/internal/knowledge/companies/{companyId}/capture-declared-profile` accepts only `{"captureId":"opaque-printable-key"}` (1–128 ASCII characters) and requires the existing `X-Internal-Secret`. It is an explicit operation after a completed operational update/import. There is no capture on GET, automatic scan, CSV parser, public route, new database or ACL change.

The operation freezes that company's current region, distinct A–U industry sections, decimal revenue and employee count in the existing operation journal. It writes an immutable Context company material with sourceId `company-operational-declared-profile`, actual reserved `knownAt`/`event_payload.retrievedAt`, and canonical JSON text `{companyId,region,industrySections,revenue,countOfEmployees}`. Currency and period remain null because the operational revenue column has neither; amount is an invariant decimal string. Missing fields remain null; zero remains zero. Region describes a declaration/registration and cannot prove geographic operations or exclusion.

The returned existing `CompanyProfile` contract has an additive `declaredProfile` block with these fields and exactly one immutable `sourceRefs` entry. The material hash covers the normalized material envelope and text, matching ContextService's writer. The capture verifies the returned envelope, hash, company scope, source marker and time before publishing the knowledge revision. Internal profile writes additionally require declared fields to match the exact snapshot. Legacy null blocks are omitted on serialization to preserve historical immutable hashes.

Numeric `industryCodes`, documentary `exposures`, description, name and their source references are preserved from existing knowledge. The new block has its own snapshot reference; replacing a declared block replaces its previous snapshot refs in the new profile, while historical revisions and documentary refs remain intact. For operational-only companies, numeric codes/exposures start empty and description explicitly states `Operational declared company profile; no documented financial exposure established`. A–U sections are never converted into numeric codes or financial exposure.

Retry the same captureId after timeout/unknown outcome: the operation resumes or returns its frozen original fields, identity and time, even when current operational fields changed. A new captureId creates a new version. Capture and new public knowledge writes atomically compare the latest committed revision under the existing knowledge advisory lock, without limiting the check to the frozen timestamp; a race yields 409 and requires a new request/key rather than discarding a newer declared block. An already-written exact revision/hash remains an idempotent success before that comparison and cannot replace a later head. Previously frozen public operations remain readable. Source publication can precede a failed profile write; that orphan immutable source is not a confirmed profile revision.

Company knowledge reads retain existing `asOf` selection. Captures are not backdated; older revisions without the block remain unknown. Declared snapshots are profile signals only, never documentary financial exposure, contract identifiers or payment-derived finances. Consumers must enforce that distinction in code and keep role framing separate from canonical facts.

DB-free regressions are in `DeclaredCompanyCaptureTests` and `PublicKnowledgeTests`: explicit internal route, exact snapshot/hash, nulls/decimal precision, historical selection, repeated/lost-response capture, concurrent knowledge changes, declared retention on documentary edits, and corrupt Context responses. Native command: `dotnet test Tests/CompanyService.Tests.csproj -c Release --filter 'FullyQualifiedName~DeclaredCompanyCaptureTests|FullyQualifiedName~PublicKnowledgeTests|FullyQualifiedName~PublicKnowledgeMvcTests|FullyQualifiedName~ContextCompanyMaterialsClientTests'`. It excludes the existing PostgreSQL-dependent classes; no database is needed by these fixtures.
